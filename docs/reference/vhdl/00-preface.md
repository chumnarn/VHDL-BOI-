## 1. คู่มือนี้ทำไมต้องมี

RTL ที่ผ่านการทดสอบระดับ functional ไม่ได้แปลว่าจะผ่านการสังเคราะห์ การวางวงจร
หรือการทำงานร่วมกับโมดูลอื่นในระบบ ปัญหาส่วนใหญ่ที่พบในงาน ASIC จริงไม่ได้เกิดจาก
"คิดตรรกะผิด" แต่เกิดจากรายละเอียดของภาษาที่ไม่ได้ระวัง เช่น

- เขียน `case` ไม่ครบทุกกรณี ทำให้เกิด latch ในวงจรจริง
- ใช้ signal แทน variable ในโมดูลที่มีนาฬิกา ทำให้ได้ latch แม้ดูเหมือนโค้ดถูก
- อ่าน output port ของตัวเองในมาตรฐาน VHDL-2002 ซึ่งทำไม่ได้ แต่ในมาตรฐาน VHDL-2008 ทำได้
  ทำให้โค้ดพังเมื่อนำไปรันบนเครื่องมือของห้องเรียน
- เขียน `always` แบบ blocking ในบล็อกที่มีนาฬิกา ทำให้ผลจำลองไม่ตรงกับวงจรจริง
- ข้าม clock domain โดยไม่มี synchronizer

คู่มือนี้รวบรวมรูปแบบที่ผ่านการตรวจสอบจริงเหล่านี้ไว้ในที่เดียว เพื่อให้ผู้เรียน
ตรวจสอบย้อนกลับได้ทุกข้อ ไม่ต้องเชื่อคำว่า "ควรจะถูกต้อง" อย่างเดียว

## 2. ขอบเขตและสิ่งที่ไม่อยู่ในขอบเขต

### 2.1 อยู่ในขอบเขต

- ภาษา VHDL ที่ใช้เขียน RTL ที่สังเคราะห์ได้ ตั้งแต่โครงสร้าง design unit
  ชนิดข้อมูล การตั้งชื่อ ไปจนถึงรูปแบบการเขียน combinational, sequential,
  FSM, pipeline, interface และ clock domain crossing
- โครงสร้างโค้ดสำหรับโปรเจกต์จริง: package, generic, procedure, function, generate
- ขอบเขตของภาษาที่สังเคราะห์ได้ (synthesis subset) และสิ่งที่สังเคราะห์ไม่ได้
- รูปแบบ testbench แบบ self-checking สำหรับตรวจสอบ RTL
- คำสั่งตรวจสอบด้วย GHDL และเครื่องมืออื่นที่ใช้ในคอร์ส

### 2.2 ไม่อยู่ในขอบเขต

- **SystemVerilog และ UVM** — คู่มือนี้เป็น VHDL เท่านั้น เมื่อโปรเจกต์ต้องการ
  constrained random, functional coverage หรือ assertion ในระดับสถานการณ์
  ต้องย้ายไปใช้ SystemVerilog ตามแนวทางในบทที่ 4 ของคู่มือหลักสูตร
- **การออกแบบระดับสถาปัตยกรรม** — เช่น การเลือกโปรโตคอลระดับบัส, partitioning
  ระหว่างบล็อก หรือการทำ power budget ระดับระบบ
- **ข้อมูลจากการวัดจริงของซิลิคอน** — ตัวเลขทั้งหมดในตัวอย่างเป็นข้อมูลสมมติ
  เพื่อการสอน ไม่ใช่ค่าจาก PDK IHP SG13G2 หรือ SKY130
- **ผลการ sign-off** — การรัน DRC/LVS ผ่านไม่ได้แปลว่าผ่านเงื่อนไขการส่งผลิต

## 3. มาตรฐานภาษาที่ใช้เป็นเกณฑ์

คู่มือนี้ใช้เกณฑ์สองชั้น เพราะสภาพแวดล้อมจริงของห้องเรียนมีทั้งสองแบบ

| ชั้น | มาตรฐาน | เหตุผล |
|---|---|---|
| หลัก | VHDL-2008 (IEEE 1076-2008) | เป็นมาตรฐานที่เครื่องมือสมัยใหม่รองรับและเป็นเป้าหมายของการพัฒนาโค้ด |
| รองรับ (ต้องผ่านด้วย) | VHDL-2002 (IEEE 1076-2002) | ModelSim/Questa ของห้องเรียนตั้งค่า `VHDL93 = 2002` ถ้าโค้ดใช้ฟีเจอร์ของ VHDL-2008 จะคอมไพล์ไม่ผ่านในห้องเรียน |

ข้อสรุปที่ใช้ทั้งคู่มือ: **โค้ด RTL ทุกชิ้นต้องคอมไพล์ผ่านทั้งสองมาตรฐาน**
ตัวอย่างโค้ดทุกชิ้นในชุดนี้ถูกตรวจด้วยคำสั่งต่อไปนี้และบันทึกผลไว้ใน `reports/`

```bash
ghdl -a --std=08 --workdir=work <src...> <tb...>   # วิเคราะห์ด้วย VHDL-2008
ghdl -e --std=08 --workdir=work <tb_entity>          # สร้าง executable
ghdl -r --std=08 --workdir=work <tb_entity>          # จำลอง
ghdl -a --std=02 --workdir=work02 <src...> <tb...>  # วิเคราะห์ด้วย VHDL-2002
ghdl -e --std=02 --workdir=work02 <tb_entity>
ghdl --synth --std=08 --workdir=work <top_entity>    # ตรวจว่าสังเคราะห์ได้
```

> **ห้ามใช้ฟีเจอร์เฉพาะ VHDL-2008 ในโค้ดที่ต้องส่งให้ผู้เรียน**
> เช่น `process (all)`, `std.env.stop`, `to_string`, `integer'image`
> ที่ผันกลับ และ external name ที่ใช้อ้าง signal ภายในจาก testbench
> ถ้าจำเป็นต้องใช้ ให้แยกเป็นไฟล์เฉพาะและระบุชัดเจนใน README ของโปรเจกต์

### 4.1 ลำดับการอ่านที่แนะนำ

| ผู้อ่าน | ลำดับ |
|---|---|
| เพิ่งเริ่มเขียน RTL | 00 → 01 → 03 → 04 → 05 → 06 → 11 → 15 |
| รีวิวโค้ดของคนอื่น | 03 → 13 → 15 |
| ย้ายจาก Verilog | 14 → 01 → 02 → 04 → 05 |
| เตรียมออกแบบ interface | 07 → 08 → 09 → 10 |

### 4.2 ตัวอย่างโค้ดในคู่มืออยู่ที่ไหน

ตัวอย่างทุกชิ้นไม่ได้วางไว้ในเอกสารอย่างเดียว แต่มีไฟล์จริงให้รันตรวจได้ที่

```text
code/reference/vhdl/
├── STYLE-CONTRACT.md          # ข้อตกลงรูปแบบที่ตัวอย่างทุกชิ้นยึด
├── scripts/check_example.sh   # ตรวจตัวอย่างหนึ่งตัวด้วย 6 เกณฑ์
├── run.sh                     # ตรวจทุกตัวอย่างตามลำดับ
└── examples/
    ├── ex00_minimal_dut/
    ├── ex01_alu_comb/
    ├── ...
    └── ex12_cdc_handshake/
```

วิธีตรวจตัวอย่างหนึ่งตัว (Linux / WSL2 / macOS / Git Bash)

```bash
cd code/reference/vhdl
bash scripts/check_example.sh ex01_alu_comb alu_comb tb_alu_comb
```

ผลที่ต้องเห็นเมื่อผ่านทั้งหมด

```text
GHDL_ANALYZE_08: PASS (ex01_alu_comb)
GHDL_ELABORATE_08: PASS (tb_alu_comb)
GHDL_RUN: PASS (tb_alu_comb) [GOLDEN_ALU_COMB_PASS]
GHDL_ANALYZE_02: PASS (ex01_alu_comb)
GHDL_ELABORATE_02: PASS (tb_alu_comb)
GHDL_SYNTH: PASS (alu_comb)
```

## 6. การตรวจสอบงานของผู้เรียน

ก่อนส่งงาน RTL ทุกชิ้น ให้ทำตามรายการนี้

- [ ] คอมไพล์ผ่านทั้ง `--std=08` และ `--std=02` (ดูบท 12)
- [ ] จำลองแล้ว testbench จบด้วย marker PASS ไม่ใช่แค่ไม่ขึ้น error
- [ ] `ghdl --synth` สร้าง netlist ได้สำหรับโมดูลที่เป็น RTL
- [ ] ไม่มี warning ระดับที่ทำให้ผลจำลองไม่น่าเชื่อถือ (เช่น latch ที่ไม่ตั้งใจ)
- [ ] มี corner case ครบ: reset, ค่าขอบเขต, back-to-back, ค่า X
- [ ] ชื่อ signal ตรงกับเวอร์ชัน Verilog ของโมดูลเดียวกัน (ถ้าโปรเจกต์ใช้ทั้งสองภาษา)

เช็กลิสต์ฉบับเต็มอยู่ใน [บทที่ 15](15-checklists.md)

## 7. ข้อจำกัดของคู่มือ

- ตัวเลขทั้งหมดในตัวอย่างเป็นข้อมูลสมมติเพื่อการสอน ไม่ใช่ค่าจากซิลิคอนจริง
- การผ่าน `ghdl --synth` เป็นการพิสูจน์ว่าโค้ดอยู่ในขอบเขตที่เครื่องมือรองรับ
  ไม่ใช่การรับรองผลการสังเคราะห์ของเครื่องมือเชิงพาณิชย์
- คู่มือนี้ไม่ครอบคลุมทฤษฎีของตรรกะดิจิทัลเชิงลึก ให้ใช้
  [ภาคทฤษฎีของคู่มือหลักสูตร](../../theory/01-digital-fundamentals.md) ประกอบ
- เอกสารประกอบการสอนของแต่ละเครื่องมือเป็นแหล่งอ้างอิงสุดท้าย คู่มือนี้เป็นแนวทาง
  ไม่ใช่สิทธิ์แทนเอกสารทางการ

## แบบฝึกหัดท้ายบท

1. ติดตั้ง GHDL ใน WSL2 ด้วยคำสั่ง `sudo apt-get install -y ghdl` แล้วรัน
   `bash code/reference/vhdl/scripts/check_example.sh ex00_minimal_dut dff_simple tb_dff_simple`
   บันทึกผลลัพธ์ที่ได้ พร้อมระบุว่าเครื่องมือรุ่นใด
2. แก้ `ex00_minimal_dut` ให้ใช้ **asynchronous reset** แล้วรันซ้ำ จากนั้นอธิบาย
   ว่าผลลัพธ์ที่เห็นต่างกันอย่างไรเมื่อปลด reset ระหว่างที่นาฬิกาขอบ
3. อ่านบทที่ 13 แล้วเขียนรายการข้อผิดพลาด 5 ข้อที่คุณเคยเจอ และระบุว่าอยู่ในหมวดใด
4. ร่าง "หน้ากฎของทีม" ของคุณเอง 3–5 ข้อ โดยอ้างอิงบทที่ 03 และบอกว่าข้อไหนของคุณ
   ที่ต่างจากคู่มือและเพราะอะไร

## คำถามท้ายบท

1. ทำไมโค้ดต้องคอมไพล์ผ่านทั้ง `--std=08` และ `--std=02` แม้คู่มือจะเรียก VHDL-2008
   เป็นมาตรฐานหลัก
2. ข้อความใน `report "..."` ของ VHDL มีข้อจำกัดอะไร และมีผลอย่างไรต่อข้อความภาษาไทย
